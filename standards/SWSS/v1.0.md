# Scientific Workflow Simulation Standard (SWSS) v1.0

**Status:** Draft for owner review, 2026-10-18. **Audience:** Python scientific simulation authors.

SWSS is a voluntary, independent workflow convention, not an industry certification, new scientific data format, or a dependency requirement on either application. **MUST** is required for the profile claimed; **SHOULD** is recommended with documented exceptions; **MAY** is optional.

## 1. Independent profiles

| Profile | Requirements |
| --- | --- |
| **Core** | General versioning, logs, provenance, isolated outputs, truthful lifecycle |
| **SimShelf** | Core plus optional SimShelf recorder compatibility, progress, metrics and automatic capture |
| **Wavez** | Core plus verified Wavez WVZ1 scene recording |
| **Full** | Core plus both optional profiles |

A project MUST identify which profiles it claims, tested tool versions and deviations. SimShelf and Wavez remain independent products; users may adopt either or neither. Existing simulations are modernized one by one only when selected for future runs. The contracts in each software's own repository override this workflow guidance.

## 2. Core profile: scientific integrity

1. Integrating workflow features MUST NOT silently change numerical equations, timestep, grid, precision, RNG stream, boundary conditions or other scientific behavior. Preserve a before/after reference or explicitly document the approved scientific difference.
2. Document all experiment parameters and resolved runtime values. Record start time, model version, actual arguments, solver configuration, grid extent/resolution, time units, channel/coordinate units, output cadence and random-seed/state policy. SHOULD record dependency versions, GPU/backend, source identity, external input hashes and restart lineage.
3. Source versioning follows MAJOR.MINOR.PATCH. Any accepted change to executable code or its logging/export/instrumentation behavior MUST bump the declared version before the next recorded run. Breaking scientific changes normally use major; substantive scientific revisions minor; corrections/instrumentation patch. Runtime argument differences alone do not bump the source version. Capture exact source bytes/hash independently: matching labels do not guarantee identical code. SHOULD warn/block in CI if tracked code changes without version bump; this is not a built-in SimShelf auto-bump.
4. Every run MUST write a uniquely named, timestamped, human-readable log including version, parameters, status and useful errors. UTC timestamp format SHOULD be YYYYMMDDTHHMMSSZ with an additional collision-resistant run ID. Flush/close on normal shutdown and handled failure; forced termination can leave partial evidence. Avoid uncontrolled per-cell progress writes.
5. Each run MUST have a unique output directory, including concurrent runs, and MUST NOT silently overwrite historical output. File paths, parameter conventions, inputs and outputs must be documented.
6. Failure MUST use a nonzero exit code. Incomplete outputs MUST NOT be labeled verified complete. Keep visualization recording and diagnostic/checkpoint cadences independent of the solver integration step. Wavez scenes are not restart checkpoints.
7. Diagnostics SHOULD be defined mathematically with real units where applicable, and computed from source solver state rather than rendered colors. A numerical measurement is not an image-derived impression.
8. Large binary results SHOULD remain outside Git history by default and have their own backup strategy; a reference-only artifact is not a backup. Never place credentials in logs/metadata.

### Suggested project layout

Use a source root containing simulate.py, README.md, requirements.txt, logs/, and outputs/. Each run creates a unique outputs/run_TIMESTAMP_ID directory containing logs/run.log, summary.json and measurements.csv, with scene.wvz only for the Wavez profile and checkpoint.npz only where restart data is actually supported. Local logs/ beside the entry point is a convenience mirror; each run's output folder is the capture source. Exclude generated logs/outputs from source snapshots and Git as appropriate.

## 3. Optional SimShelf profile

The simulation MUST be registerable with a stable Python entry point and appropriate simshelf.toml. Declare a literal SIMSHELF_VERSION assignment in the configured version_file. This human label, source snapshot and structural fingerprint are distinct. Prefer statically discoverable argparse declarations or a separately validated simshelf-arguments.json schema.

For runs launched from SimShelf, the script MUST write capturable output to the effective run output folder from the joined run context or SIMSHELF_OUTPUT_DIR. Explicit --output precedence and standalone behavior MUST be unambiguous and tested; SimShelf does not redirect arbitrary writes. Concurrent runs need distinct non-overlapping capture directories.

**Automatic log capture is required with no post-run upload:** write a timestamped real .log file directly to the effective output folder's logs/ subdirectory. In SimShelf file-capture settings, place a COPY rule matching **/*.log before wildcard ignore rules, and verify file/run size budgets. SimShelf must automatically show that log in the run's Files record after final capture. Native process stdout/stderr is separately available in Logs. A second logging handler MAY also create a local mirror next to simulate.py; source-adjacent logs alone are NOT automatically ingested by current output-directory capture. Avoid symlinks. Verify normal, failed and cancelled runs and inspect skipped/oversized artifacts. File capture may remain incomplete after interrupted processes.

Finite jobs MUST report truthful progress by default where possible: use the structured run.progress(current=..., total=..., stage=...) API only with an explicitly enabled compatible library and installed SimShelf package, OR print a whole-line supported form such as 'Step 1000 of 50000' with flushing and explicitly select the Step counts parser. Neither adapter is universal automatic inference. Do not conflate step counts with scientific time or consider 100% proof of successful computation.

Where scientifically meaningful, SHOULD call run.metric(name, value, step=..., sim_time=...) from a joined run context, using finite, correctly defined quantities. SHOULD also save independent measurements.csv and summary.json. SimShelf does not infer arbitrary log numbers as stored scientific metrics.

Small text JSON/CSV/logs and useful preview images SHOULD usually be copied according to configured limits; large binary captures/checkpoints SHOULD usually be referenced with independently verified backups. File capture rules are prospective, first-match-wins; a source-local .log outside the watched folder is not included merely because it exists.

## 4. Optional Wavez profile

Use the currently supported WVZ1 .wvz format via wavez_export.SceneCapture and its documented reader. Do NOT create obsolete SSC/SIMSCP4 outputs or mislabel a custom file. Preserve actual solver timestamps, scientific units and coordinate meanings; use supported particle/mesh ID semantics and valid volume shape (nz,ny,nx) with xyz origin/spacing. Channel names must reflect actual solver quantities.

Recording cadence MUST be configurable independently of integration timestep, and recording MUST NOT change scientific RNG calls or solver state. Do not silently overwrite captures. Finalize the writer correctly; partial captures must not be declared verified complete. Acceptance MUST include an actual SceneReader data readback of samples, geometry, timestamps and channels and a viewer inspection on a representative short file. WVZ1 is visualization data, not a universal restart state.

## 5. Acceptance and adoption

For **Core**, verify unique paths, version/provenance, truthful success/failure, log and numeric baseline before/after integration. For **SimShelf**, verify discovered settings, correct effective output folder, live progress using a supported selected adapter, metrics if meaningful, native process Logs, and an automatically captured timestamped .log under Files with **no manual upload**. For **Wavez**, verify the real WVZ1 output with both SceneReader numerical comparisons and a Wavez viewer inspection. Run at least a successful short job and an intentional failure/interruption where safe.

The first SWSS reference implementation and automated version consistency checks are **future work**, not current certification. Validate one small synthetic simulation before adopting any legacy simulation. No mass migration is required.
